# Knowledge-Nest が向いている構成

Knowledge-Nest は、手元のフォルダを取り込み、出典付きの検索を CLI や MCP で提供し、その検索を評価して改善したいときに使えます。標準の日本語キーワード検索はモデルを指定せずに始められます。モデルを設定すると、RAG の回答生成や Wiki・PARA の執筆も使えます。 [サンプル資料で始める](quickstart.md)

| 選び方 | 主に用意されているもの | 選ぶ目安 |
| --- | --- | --- |
| Knowledge-Nest のプロジェクト CLI | 資料の抽出、索引、提供、引用に基づく評価と試行、Wiki・PARA | 手元の資料から既定構成で検索を立ち上げ、設定の差だけを測りたい |
| LangChain を使ったアプリ | 検索、モデル、ツールなどを組み合わせるためのライブラリと例 | アプリ固有の処理、ツール、検索や生成の流れをコードで組み立てたい |
| Qdrant のサーバー API と自作アプリ | ベクトルと付随データの保存・検索、絞り込み | ベクトルを複数のアプリで使いたい。文書の抽出や出典の管理、評価はアプリ側で設計する |

LangChain には文書を検索するエージェントや、処理の流れを組み立てる RAG の例があります。Qdrant はベクトル検索に加え、付随データを使った絞り込みの API を提供します。 [LangChain の利用例](https://docs.langchain.com/oss/python/learn) · [Qdrant の概要](https://qdrant.tech/documentation/overview/what-is-qdrant/)

文書単位のアクセス権、複数テナント運用、独自のエージェント制御が要件に入る場合は、その責任を持つアプリケーションの設計が先に必要です。比較する際は、実際の質問と正解の引用を揃えて、出典の回収と検索時間を測ります。 [評価の手順](evaluation.md)
