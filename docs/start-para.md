# PARA 入門：AI に、資料とメモを「行動に沿って」整理させる

[English](start-para.en.md) · [入門の一覧](getting-started.md)

溜まった資料やメモを AI に読ませ、PARA の4分類（Projects・Areas・Resources・Archives）にノートとして整理させます。ノートは、使い道のある資料1件ごとに1つで、資料の写しと一緒に、それを使う取り組みや領域のフォルダに入ります。人はブラウザで読み、エージェントは MCP で同じノートを引けます。

## PARA という考え方

PARA は、Tiago Forte が提唱した、デジタルの情報を整理する方法です（[解説](https://fortelabs.com/the-p-a-r-a-method-a-universal-system-for-organizing-digital-information-75a9da8bfb37/)）。

中心の考えは、**テーマではなく「行動にどれだけ近いか」で分ける**ことです。「ポンプ」「規程」「顧客A」のようにテーマで分けると、フォルダは増え続け、いま使うものが埋もれます。PARA は「この情報を、いまの仕事に使うか」で、4つに分けます。

| 分類 | 入るもの | 終わりがあるか | 例 |
|---|---|---|---|
| **Projects** | 目標と期限のある取り組み | ある | 来月のポンプ更新工事、新人研修の準備 |
| **Areas** | 続けて責任を持つ領域 | ない | 設備の定期保全、安全管理 |
| **Resources** | いつか役立つかもしれない参考情報 | ない | 部品メーカーのカタログ、業界の規格 |
| **Archives** | 上の3つで、もう動いていないもの | — | 終わった工事の記録、担当を外れた領域 |

上ほど行動に近く、下ほど遠い並びです。

- **Projects と Areas の違い**は終わりがあるかどうかです。「工事を終える」は Projects、「設備を保ち続ける」は Areas です。
- **Areas と Resources の違い**は責任があるかどうかです。自分が守る基準のある領域は Areas、関心があるだけの話題は Resources です。
- **情報は動く**。工事が終われば、その資料は Projects から Archives へ移ります。分類は固定の棚ではなく、いまの仕事を映すものです。
- **仕事の知識と、自分の知識を分けて育てる**。Projects と Areas には、いまの仕事・テーマの知識が集まり、仕事とともに入れ替わります。Resources には、自分のスキルや関心の知識が集まり、仕事が変わっても残って積み上がります。Knowledge-Nest では、仕事の枠（Projects と Areas）は人が `rules.md` に書き、関心の枠（Resources の話題）は AI が資料に合わせて足していきます。

## Wiki との違い

| | Wiki | PARA |
|---|---|---|
| 目的 | みんなが使う知識を作る（チームの共有知識） | 自分の仕事を進める（自分の取り組みの資料） |
| まとまりの単位 | テーマごとのページ | 資料1件ごとのノート（要点と使い道） |
| いちばん上の区分 | テーマの区分 | Projects、Areas、Resources、Archives。その下に、取り組み・領域・話題ごとのフォルダ |
| 区分を決めるもの | AI（`rules.md` の分類に足していく） | Projects と Areas は人が `rules.md` に書く。Resources の話題は AI が足す |
| 資料の置き場所 | `raw/` | ノートと同じフォルダの `資料/` |
| アーカイブ | 古くなったページをしまう | 終わった取り組みを、ノートと資料ごと Archives へ移す |
| ホーム | 件数と最近更新したページ | 4区分の説明と件数、進行中の Projects の一覧 |

コマンド、画面、出典の決まりは Wiki と共通です。「知識の事典」を作るなら Wiki、「仕事の机」を整えるなら PARA です。

## こんなときに

- 調べもののメモや資料が溜まり、どこに何があるか分からない
- 案件ごとの資料と、続けて担当する業務の資料を分けて持ちたい
- 終わった案件の資料を、消さずに片づけたい

## ほかの方法と比べて

PARA は、続けるのに手間がかかる方法です。資料が来るたびに「これはどの取り組みに使うか」を考えて振り分け、取り組みが終われば片付ける。その手間で、途中から崩れがちです。Knowledge-Nest は、この手間を AI とコマンドが受け持ち、枠を決めるのは人に残します。

- **振り分けるだけでなく、使い道まで書く。** ノートは「この資料を、この取り組みにどう使うか」を書いたものです。フォルダに入れて終わる自動振り分けと違い、あとで開いたときに、なぜここにあるのかが分かります。
- **枠を決めるのは人、AI はそれを守る。** AI が置けるのは、あなたが `rules.md` に書いた取り組みと領域だけです。一覧にない場所へのノートは保存せず、資料は未反映のまま残します。取り組みを書き足して `nest ingress --pending` すれば、そこに置かれます。
- **取り組みのフォルダが、そのまま使える。** ノートの隣の `資料/` に資料の写しが入るので、取り組みのフォルダを開けば、ノートと元の資料がそろっています。
- **終わったら一度で片付き、いつでも戻せる。** `nest archive` が、ノート、資料の写し、ほかのノートからのリンク、`rules.md` の行をまとめて Archives へ移します。`--restore` や `nest undo` で戻せます。期限を過ぎた取り組みは `nest lint` が知らせます。
- **エージェントも、いまの仕事の文脈で引ける。** ノートは MCP でも引けるので、Claude などに「来月の工事で交換する部品は？」と聞けば、その取り組みのノートを根拠に答えます。出典との照合、作業の取り消し、ブラウザの画面は Wiki と共通です。

## 1 執筆モデルを用意する

ここでは、手元で動く Ollama の `qwen3:4b` を使います。

```sh
nest config set llm --provider ollama --model qwen3:4b
```

## 2 PARA を作る

```sh
nest init para ./para --purpose "設備保全の仕事に関わる資料とメモを整理する"
cd para
```

`init para` は、`site/` の下に4分類のディレクトリと、決まり（`rules.md`）を作ります。

次に、`rules.md` の `## Projects` に、いま進めている取り組みを、`## Areas` に、続けて責任を持つ領域を書きます。AI はここにない取り組みや領域を作りません。期限は `YYYY-MM-DD` で書くと、過ぎたときに `nest lint` が知らせます。`rules.md` のうち AI が書き足すのは `## Resources` の話題だけで、ほかはあなたが書く部分です（`## Archives` には `nest archive` が取り組みの行を移します）。

```markdown
## Projects

- ポンプ更新工事：2026-12-20 までに主ポンプを交換する

## Areas

- 設備の定期保全：故障による停止を年 2 回以下にする
```

`--purpose` には、この PARA が何のための場所かを書きます。あとで `KnowledgeNestfile.yaml` の `about.purpose` で直せます。

## 3 資料を取り込む

```sh
nest ingress ../inbox
```

AI が資料を1件ずつ読み、使い道のある資料ごとにノートを書いて、それを使う場所に置きます。ノートは、何の資料か、**要点**（その取り組み・領域に使うところ）、**使い道** を書いたものです。

1. Projects のどれかに使う資料は `Projects/<取り組み>/<資料の名前>`
2. Areas のどれかの仕事に使う資料は `Areas/<領域>/<資料の名前>`
3. それ以外で役立ちそうな資料は `Resources/<話題>/<資料の名前>`。新しい話題は `rules.md` の `## Resources` に足されます
4. どこにも使わない資料にはノートを書かず、「得るものなし」として記録します

AI には、置ける場所（決まりの取り組み・領域と、これまでの話題）の一覧を渡します。AI が決めるのは置き場所だけで、ノートの名前は資料の名前になります。1つの資料のノートは1か所だけで、AI が別の場所にも書いたときは最初の1つを残し、ほかは `NOTE_SKIPPED` の警告にします。資料の写しは、ノートと同じフォルダの `資料/` に置かれ、ノートの出典はそこを指します。決まりにない取り組みにノートを置こうとしたときは保存せず、`PLACE_INVALID` の警告を出します。その資料は未反映のまま残るので、決まりに取り組みを足してから `nest ingress --pending` で取り込み直せます。本文の数字・日付・引用が資料にないときは、`UNSUPPORTED_LITERAL` の警告が出ます。`nest ingress https://...` のように URL を渡すと、Web のページも取り込めます。その前に1回 `nest browser` を実行し、nest 専用のブラウザで読ませたいサイトにログインしてから閉じてください（[詳しく](wiki.md)）。時間がかかるときは、表示された作業 ID を `nest progress <作業ID>` に渡して進み具合を見られます。

## 4 読む：ブラウザと MCP

```sh
nest serve
```

`serve` は、ノートを Web と MCP の両方で提供します。

- **ブラウザで**: `http://127.0.0.1:4319` を開くと、左のファイルツリーのいちばん上に Projects・Areas・Resources・Archives が並び、開いたノートや原本と、それに対してできること（質問、指示による修正、検査）は右に出ます。左上の **資料を取り込む** に URL かファイルを渡すと、そのまま取り込めます。ホームには、目的、質問の欄、4区分の説明とノートの件数、最近更新したノートが出ます。
- **エージェントから**: MCP クライアントの設定に登録すると、Claude などが、あなたの整理したノートを根拠に答えます。

## 5 使い続ける

| したいこと | コマンド |
|---|---|
| ノートを根拠に質問する | `nest query "来月の工事で交換する部品は？"` |
| 書き方を直させる | `nest instruct <ノート> "要点を3つに絞って"` |
| 新しい取り組みを始める | `rules.md` の `## Projects` に書き足す |
| 今後の分け方の決まりを足す | `nest instruct --persistent "カタログ類は Resources に置く"` |
| 終わった取り組みを片づける | `nest archive Projects/<取り組み>`（ノートと資料のフォルダごと `Archives/<取り組み>` へ移り、`rules.md` の行も `## Archives` へ移る。ほかのノートからのリンクも付け替わる。`nest archive --restore Archives/<取り組み>` か `nest undo` で戻せる） |
| ノート1つだけしまう | `nest archive <ノート>` |
| 期限切れや食い違いを見つける | `nest verify`、`nest verify --content` |
| 作業を取り消す | `nest undo <作業ID>` |

アーカイブしたノートは、通常の質問の対象から外れます。消えるわけではなく、読むことも戻すこともできます。

## 6 うまくいかないとき

| 症状 | 対処 |
|---|---|
| 思った場所に入らない | `rules.md` の `## Projects` と `## Areas` に、取り組みと領域を書く。決まりを `instruct --persistent` で足す |
| `PLACE_INVALID` の警告 | 決まりにない取り組み・領域に置こうとしたノートは保存されない。決まりに足して `nest ingress --pending` |
| `MODEL_REQUIRED` | `models.writer.model` を設定する |

そのほかは [Wiki 入門](start-wiki.md#9-うまくいかないとき) と [困ったときは](troubleshooting.md) にあります。
