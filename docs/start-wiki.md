# Wiki 入門：AI に、根拠付きの知識のページを書かせる

[English](start-wiki.en.md) · [入門の一覧](getting-started.md)

資料を AI に読ませ、テーマごとに整理された Wiki のページを書かせます。ページには、書くのに使った資料が出典として付きます。人はブラウザで読み、エージェントは MCP で同じページを引けます。

## LLM-Wiki という考え方

これは Andrej Karpathy が提案した LLM-Wiki の考え方に沿った仕組みです（[原文の gist](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)）。

- RAG は、質問のたびに資料の断片を探し、その場で答えを組み立てます。読んだ結果は残りません。
- LLM-Wiki は、AI が資料を読んだ結果を、ページとして書き溜めます。新しい資料が来れば関係するページを書き足し、知識が育っていきます。
- 人は資料を選んで渡し、問いを立て、指示します。要約、ページ同士のつなぎ、更新は AI が受け持ちます。

Knowledge-Nest は、これに「出典と照合」を足しています。各ページは書くのに使った資料を出典として持ち、本文の数字・日付・「」の引用が出典の資料にそのままあるかを、プログラムが照らして示します。

## こんなときに

- 散らばった手順書や議事録から、新人が読めるナレッジベースを作りたい
- 人が読む知識と、エージェントが引く知識を、同じものにしたい
- 規程やマニュアルの食い違い、古くなった記述を見つけたい

## 役割分担

| 役割 | 担い手 |
|---|---|
| 資料を選んで渡す、質問する、指示する | 人 |
| 資料を読む、ページを書く、書き直す | AI（設定したモデル） |
| 出典の記録と照合、原本と版の保存、作業の記録 | Knowledge-Nest |

人はページを直接編集しません。直したいときは、指示で直させます。そのおかげで、ページは出典を持ったまま保たれます。

## 1 執筆モデルを用意する

ここでは、手元で動く Ollama の `qwen3:4b` を使います。

```sh
nest config set llm --provider ollama --model qwen3:4b
```

## 2 Wiki を作る

```sh
nest init wiki ./wiki --purpose "設備保全の手順と部品情報をまとめる"
cd wiki
```

`--purpose` には、この Wiki が何のための場所かを1〜2行で書きます。これはトップページの説明になるだけでなく、AI が「何をページにして、何を範囲外とするか」を決める基準にもなります。あとで `KnowledgeNestfile.yaml` の `about.purpose` と `about.out_of_scope` で直せます。

## 3 資料を取り込む

資料は、Wiki のフォルダの `raw/` に置いて取り込みます。`raw/` の外のファイルやフォルダを渡しても、`raw/` にコピーしてから読みます。AI は `raw/` の資料を読むだけで、書き換えません。AI が書いたページは `wiki/` に、ページの書き方の決まりは `rules.md` にあります。

```sh
cp ../manuals/*.md raw/
nest ingest raw/
```

`raw/` に資料を足したら、足したファイルを `nest ingest raw/<ファイル>` で1件ずつ取り込むのがおすすめです（フォルダごと渡すと、1回で AI が読めるのは合計 16,000 文字までです）。

`ingress` は、次の順で進みます。

1. 資料を、版を付けて原本として保存する
2. AI が資料を読み、関係するページを書き直したり書き足したり、新しいページを作ったりする。Wiki に足すことのない資料なら、ページは書かず「得るものなし」と記録する
3. ページに、使った資料を出典として加える。本文の数字・日付・「」の引用で、出典にないものは警告する
4. 変わったページの一覧を返す

数分かかることがあります。表示された作業 ID を `nest progress <作業ID>` に渡すと、進み具合を見られます。原本の保存だけ先に済ませ、読み書きは後でしたいときは `--source-only` を付け、あとで `nest ingress --pending` を実行します。

Web のページも、URL を渡せば取り込めます。HTML、PDF、Markdown、Office 文書を取得し、その時点の内容を原本として `raw/<ホスト名>/<パス>` に保存します。同じ URL をもう一度取り込むと、同じ資料の新しい版になります。Web のページは、nest 専用のブラウザのプロファイルで開いて読みます。最初に1回 `nest browser` を実行し、開いたブラウザで読ませたいサイトにログインしてから閉じてください。専用プロファイルがないと、URL の取り込みは `BROWSER_NOT_READY` で止まります（[詳しく](wiki.md)）。

```sh
nest ingress https://example.com/manuals/pump
```

## 4 読む：ブラウザと MCP

```sh
nest serve
```

`serve` は、ページを Web と MCP の両方で提供します。

**ブラウザで**: `http://127.0.0.1:4319` を開きます。

| 列 | 内容 |
|---|---|
| 左 | どこに何があるか。**資料を取り込む**（URL かファイルを渡す）、ホーム、作業の履歴、運用の決まりと、ファイルツリー。**ページ** は AI がまとめた記事、**原本** は取り込んだ資料そのもの |
| 右 | 開いたものと、それに対してできること。ページなら本文と出典の下で、質問、指示による修正、検査ができる。原本なら取り込んだ本文と、それを出典にしているページが出る |

ホームには、目的と範囲、質問の欄、ページ・原本・未反映の原本・未対応の指摘の件数、最近更新したページ、最近の作業が出ます。開いた時点で、次にすることが分かります。

**エージェントから**: MCP クライアントの設定に登録すると、Claude などが、人の読んでいるのと同じページを根拠に答えます。ページは `wiki/` に HTML としても保存され、サーバーなしでも読めます。

## 5 質問する

```sh
nest query "ポンプの点検はいつですか"
```

`query` は、元の資料ではなく Wiki のページを検索し、出典付きで答えます。出典は、答えに使ったページと、そのページの出典の資料までたどれます。目的の範囲外の質問には、範囲外だと答えます。良い答えは `nest save-answer` でページとして保存できます。質問するほど Wiki が育ちます。

## 6 直す：指示と決まり

```sh
nest instruct <ページ> "点検前の確認事項を箇条書きにしてください"
nest instruct --persistent "手順は番号付きで書く"
```

| 指示の種類 | 例 | 扱い |
|---|---|---|
| 構成や表現の変更 | 短くして、表にして | そのまま実行する。新しい事実は足さない |
| 資料に基づく修正 | この記述は資料と違う | 出典の資料を読み直して書き直す |
| 資料にない内容の追加 | 実際は3か月で交換している | `--supplement` と `--by` で補足として記録し、それを出典にして書く |
| 今後の決まり | 今後、手順は番号付きで | `--persistent` で運用の決まりに足す。以後のすべての作業に効く |

決まりの一覧は `nest rules` で見られます。画面では、ページを開いて下の **AI に指示して直す** に書けば同じことができます。決まりは、左の **運用の決まり** から足せます。

ページの分類は、AI が取り込みのたびに付け、合うものがなければ `rules.md` の `## 分類` に足していきます。AI がするのは足すことだけです。似た分類が増えてきたら、`rules.md` を直接書き換えて、まとめたり名前を変えたりしてください。一覧から外れた分類のページは `nest lint` が知らせるので、`nest instruct <ページ> --category <分類>` で付け替えます。分類の合っていないページは、`nest lint --content` が挙げます。[詳しく](wiki.md#分類)

## 7 点検する

```sh
nest verify
nest verify --content
```

| 検査 | 内容 | モデル |
|---|---|---|
| `verify` | 出典の資料があるか、その版が古くないか、本文の数字・日付・引用が出典にあるか、リンク切れ、どこからも参照されないページ | 要らない。速く、毎回同じ結果 |
| `verify --content` | ページ同士の矛盾、新しい資料と既存ページの食い違い、重複 | 要る。指摘の候補で、誤検出もある |

指摘は直さず、示すだけです。どちらが正しいかを人が判断し、指示で直します。確認した指摘は `nest issue <ID> resolved`（または `dismissed`）にすると、次から出なくなります。

## 8 取り消す、しまう

- **取り消す**: 取り込みも指示も、1回が1つの作業として記録されます。結果が望ましくなければ `nest undo <作業ID>` で戻せます。資料の原本は書き換えられません。
- **しまう**: 古くなったページは `nest archive <ページ>` でアーカイブします。目次と通常の質問の対象から外れますが、ページは残り、リンクも切れません。`--restore` で戻せます。

## 9 うまくいかないとき

| 症状 | 対処 |
|---|---|
| `MODEL_REQUIRED` | `models.writer.model` を設定する。`init` の `--llm-model` でも指定できる |
| `UNSUPPORTED_LITERAL` の警告 | 本文の数字・日付・引用の一部が、出典の資料に見つからなかった。ページは保存されている。ページを開いて確かめ、違っていれば指示で直す |
| `BUILD_BUSY`、`DB_BUSY` | 前の作業が終わるのを待つ。`progress` で進み具合を確かめる |

そのほかは [困ったときは](troubleshooting.md) にあります。
