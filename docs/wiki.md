# Wiki・PARA の使い方

Wiki は資料を引用したページを作ります。PARA は同じ操作で、Projects・Areas・Resources・Archives に沿ってノートを整理します。

## 最初のページを作る

リポジトリのルートで、ローカル Ollama を起動し、`qwen3:4b` を用意します。例では [サンプル資料](../examples/manuals/maintenance.md) を使います。

```sh
nest init wiki ./wiki-demo --purpose "設備保全の手順をまとめる" --llm-provider ollama --llm-model qwen3:4b --no-ocr
cd wiki-demo
nest ingress ../examples/manuals
nest serve
```

PARA を作る場合は `init para ./para-demo` に読み替えます。ブラウザで `http://127.0.0.1:4319` を開きます。生成した HTML はプロジェクト内の `site/` に保存されます。

## 画面の見かた

左の列は、どこに何があるかを示します。右の列は、開いたものと、それに対してできることを示します。

| 左の列 | 内容 |
|---|---|
| **資料を取り込む** | URL かファイルを渡して取り込む |
| **ホーム**、**作業の履歴**、**運用の決まり** | 全体の状況、これまでの作業、AI に守らせる決まり |
| **ページ** | AI が資料を読んでまとめた記事。フォルダごとに並ぶ |
| **原本** | 取り込んだ資料そのもの。パスのフォルダごとに並び、Web の資料は「Web」の下にホストごとに並ぶ。まだページに書かれていない原本には **未反映** と出る |
| **アーカイブ** | しまったページ。あるときだけ出る |

| 右の列に開くもの | 内容 | できること |
|---|---|---|
| ホーム | 目的と範囲、ページ・原本・未反映・未対応の指摘の件数、最近更新したページ、最近の作業 | Wiki 全体への質問、未反映の原本の反映、検査 |
| ページ | 本文と出典。本文の引用番号を押すと、出典の行へ飛ぶ | そのページへの質問、指示による修正、検査、アーカイブ。出典ごとの **引用箇所を見る** |
| 原本 | 取り込んだ本文、元の URL、それを引用しているページ | ページへの反映、URL の取り直し |
| 運用の決まり | いまの決まり | 決まりの追加 |
| 作業の履歴 | 取り込み、質問、指示、検査の記録 | 作業を開いて結果を見る、取り消す |

作業を始めると、右の列のいちばん上に、その作業の進み具合と結果が出ます。

## 画面から資料を追加する

1. 左上の **資料を取り込む** を開き、**URL** に Web のページの URL を書くか、**ファイル** でローカルのファイルを選び、**取り込む** を押します。プロジェクトのフォルダにあるファイルは、**プロジェクト内のファイルを指定する** にパスを書いても取り込めます。
2. 右に出る作業の欄で、取得・読み取り・執筆・引用検証の進捗を確認します。別の画面へ移動した場合は **作業の履歴** から開き直せます。
3. 完了後、変更されたページを開き、本文と出典を見比べます。出典の資料名を押すと、その原本の本文が右に出ます。

URL は http と https に対応し、HTML、PDF、Markdown、テキスト、Office 文書を取り込めます。Shift_JIS や EUC-JP のページは UTF-8 に直して保存します。取得した内容は `.knowledge-nest/artifacts/uploads/` に原本として残り、ページの出典は元の URL を指します。同じ URL をもう一度取り込むと、同じ資料の新しい版になります。CLI でも `nest ingress https://example.com/page` のように URL を渡せます。

`serve` の画面を他の人にも開く場合（`serve.host` を `127.0.0.1` 以外にする場合）は、`serve.access.auth` で認証を付けてください。画面から渡した URL は、`serve` を動かしているマシンから取得されます。

CLI の `ingress` も作業 ID を表示します。別の端末でプロジェクトを開き、`WORK_ID` を表示された ID に置き換えると進捗を確認できます。

```sh
nest progress WORK_ID --json
```

## 質問し、ページを直す

Wiki 全体への質問は、ホームの質問の欄に書いて **質問する** を押します。1つのページについて聞くときは、そのページを開き、下の **このページでできること** の **質問する** に書きます。本文を選択してから質問すると、その範囲についての質問になります。

ページを直すときは、同じ場所の **AI に指示して直す** に指示を書き、**指示を実行** を押します。本文を選択すると、対象の範囲に入ります。資料にない内容を根拠にする場合は、**資料にない内容を補足する** を開き、その内容と記録者を入力します。

CLI では以下の `PAGE_ID` を対象の ID に置き換えます。`cite` に渡す番号は、ページ内の引用番号です。

```sh
nest query "ポンプの点検はいつですか" --page PAGE_ID
nest cite PAGE_ID 1
nest instruct PAGE_ID "点検前の確認事項を箇条書きにしてください"
```

今後の作業にも使う決まりは、左の **運用の決まり** を開き、**決まりを追加する** に書いて登録します。CLI では `nest instruct --persistent` です。

## 検査して、必要な変更を取り消す

**検査** は引用、原本の版、リンクなどを確認します。**内容を検査** はモデルを使い、変更したページと関連ページの食い違いを調べます。全体の検査はホームの **点検する** から、1つのページの検査はそのページの **検査・アーカイブ** から行います。指摘に表示された引用と出典を開いて確認します。

```sh
nest verify
nest verify --content
```

変更を戻すには **作業の履歴** で対象の作業を開き、**取り消す** が表示されていれば押します。CLI では同じ作業 ID を `nest undo WORK_ID` に渡します。ページをしまうには、そのページの **検査・アーカイブ** の **アーカイブする** を押します。戻すには、左の **アーカイブ** からページを開いて **アーカイブから戻す** を押すか、`nest archive PAGE_ID --restore` を使います。
