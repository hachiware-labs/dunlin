# Wiki・PARA の使い方

Wiki は資料を引用したページを作ります。PARA は同じ操作で、Projects・Areas・Resources・Archives に沿ってノートを整理します。

## 最初のページを作る

リポジトリのルートで、ローカル Ollama を起動し、`qwen3:4b` を用意します。例では [サンプル資料](../examples/manuals/maintenance.md) を使います。

```sh
nest init wiki ./wiki-demo --purpose "設備保全の手順をまとめる" --llm-provider ollama --llm-model qwen3:4b --no-ocr
cd wiki-demo
cp ../examples/manuals/maintenance.md raw/
nest ingest raw/maintenance.md
nest serve
```

ブラウザで `http://127.0.0.1:4319` を開きます。PARA を作る場合は `init para ./para-demo` に読み替えます（PARA には `raw/` はなく、ページは `site/` に置かれます）。

`nest init wiki` が作るプロジェクトは、次の形です。

```
wiki-demo/
├─ raw/                    ← 原本。集めた資料を置く。AI は読むだけで書き換えない
├─ wiki/                   ← Wiki。AI が書くページ（HTML）
│   ├─ index.html          ← 目録
│   ├─ log.html            ← 作業の記録
│   ├─ overview.html
│   ├─ sources/            ← 資料ごとの要約ページ（原本ではない）
│   ├─ concepts/
│   └─ entities/
├─ rules.md                ← 決まり。ページの種類、書き方、取り込みの手順
├─ KnowledgeNestfile.yaml  ← 使うモデルなどの設定
└─ .knowledge-nest/        ← 原本から取り出した本文と版、作業の記録（作り直せる控え）
```

`nest ingest` は `nest ingress` の、`nest lint` は `nest verify` の別名です。どちらの名前でも同じ動きをします。

## LLM-Wiki との対応

Wiki は、Andrej Karpathy の [LLM-Wiki](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f) の形に沿っています。

| LLM-Wiki | Knowledge-Nest |
|---|---|
| 原本（raw sources）。人が集め、AI は読むだけ | `raw/`。画面から上げたファイルと、URL から取った資料もここに保存される |
| Wiki。AI が書いて保つページ | `wiki/` の HTML ファイル。このファイルがページそのもの |
| 決まり（schema） | `rules.md`。ページの種類、書き方、取り込みの手順 |
| 取り込み（ingest） | `nest ingest`。資料を読み、関係するページを書き直すか書き足し、足りないページを作る |
| 質問（query） | `nest query`。残したい答えは `nest save-answer` でページにする |
| 点検（lint） | `nest lint`、`nest lint --content` |
| `index`（目録） | `wiki/index.html` |
| `log`（記録） | `wiki/log.html` |

LLM-Wiki にないものが1つあります。AI が書いた文は、引用が原本と一字一句一致しなければ保存しません。

### 取り込みの進み方

1. 資料を原本として保存し、本文を取り出します。
2. AI に、新しい資料の名前（ファイル名か URL）と本文、決まり（`rules.md`）、いまあるページの一覧を渡します。
3. AI が、資料の内容をどのページに書くかを決め、文と引用を返します。
4. 引用を原本と照らし、一致した文だけを残します。新しい ID のページは作ります。

すでにあるページの扱いは、モデルによって2通りあります。`ingress` の `wiki.write` の `update` で選べます。

| `update` | 既定になるモデル | すでにあるページの扱い |
|---|---|---|
| `rewrite`（書き直す） | OpenAI、Strata | AI がまずページの一覧（ID、題名、書き出し）から、資料が関係するページを選びます。選んだページは本文と、その引用箇所も渡します。AI はそのページを新しい資料を踏まえて書き直し、食い違いがあれば両方を残して書きます。Karpathy の取り込みと同じ形で、モデルの呼び出しは2回です |
| `append`（書き足す） | Ollama | AI には本文を渡さず、返ってきた文をページの末尾に足します。前の文は消えません。小さいモデルは、ページの本文を見るとそれを写すだけで、新しい資料を書き足さないためです（`qwen3:4b` で確かめました） |

```yaml
ingress:
  modules:
    # ...
    - use: wiki.write
      with:
        model: writer
        rules: ./rules.md
        max_pages_per_job: 20
        update: rewrite
```

- 書き直しで前の文が外れたときは、`STATEMENTS_REMOVED` の警告と作業の結果に外れた文が出ます。意図した書き直しでなければ `nest undo` で戻せます。書き直したページで前と同じ文が返ってきたときは、その文の前の引用を使います。
- 書き足しでは、取り込みの時点で前の記述との食い違いに気づきません。食い違いと重複は `nest lint --content` で見つけ、`nest instruct` で直します。
- 資料の新しい版を取り込むと、古い版を引用していた文を外します。ほかの資料を引用している文は残ります。
- 引用の末尾にモデルが `: 1` や ` [1]` のような資料の番号を付けたときは、番号を外した引用が原本に1か所だけあれば、その引用として扱います。
- ページを書くときにモデルが出力できる量は 32768 トークンまで、待つ時間は 10 分までです。

### 決まり（`rules.md`）

`nest init wiki` は、次の内容の `rules.md` を作ります。取り込みと指示のたびに AI に渡されます。自分の分野に合わせて書き換えてください。

- ページの種類：`sources/…`（資料1件の要約。ID は資料の名前から作る）、`entities/…`（人・組織・製品・場所など）、`concepts/…`（考え方・手法・用語）、`overview`（全体の見取り図）
- 書き方：最初の文でそのページが何についてのものかを言う、文ごとに引用する、関係するページへリンクする、食い違いは消さずに書く
- 取り込みの手順：資料の要約を書く、ものと考え方のページを書き足すか作る、`overview` を合わせる

PARA の `rules.md` は見出しだけで始まります。すでにあるプロジェクトの `rules.md` は変わりません。

## 画面の見かた

左の列は、どこに何があるかを示します。右の列は、開いたものと、それに対してできることを示します。

| 左の列 | 内容 |
|---|---|
| **資料を取り込む** | URL かファイルを渡して取り込む |
| **目録**、**作業の履歴**、**運用の決まり** | すべてのページの一覧、これまでの作業、AI に守らせる決まり |
| **ページ** | AI が資料を読んでまとめた記事。フォルダごとに並ぶ |
| **原本** | 取り込んだ資料そのもの。パスのフォルダごとに並び、Web の資料は「Web」の下にホストごとに並ぶ。まだページに書かれていない原本には **未反映** と出る |
| **アーカイブ** | しまったページ。あるときだけ出る |

| 右の列に開くもの | 内容 | できること |
|---|---|---|
| 目録 | 目的と範囲、ページ・原本・未反映・未対応の指摘の件数、フォルダごとのすべてのページ（1行の要約付き）、最近の作業 | ページの検索、Wiki 全体への質問、未反映の原本の反映、検査 |
| ページ | 本文と出典。本文の引用番号を押すと、出典の行へ飛ぶ。節が3つ以上あるページには目次が付く | そのページへの質問、指示による修正、検査、アーカイブ。出典ごとの **引用箇所を見る** |
| 原本 | 取り込んだ本文、元の URL、それを引用しているページ | ページへの反映、URL の取り直し |
| 運用の決まり | いまの決まり | 決まりの追加 |
| 作業の履歴 | 取り込み、質問、指示、検査の記録 | 作業を開いて結果を見る、取り消す |

作業を始めると、右の列のいちばん上に、その作業の進み具合と結果が出ます。

## ページのフォルダ

ページは、1ページ1ファイルの HTML として `wiki/`（PARA は `site/`）に保存されます。このファイルがページそのもので、ほかに控えはありません。サーバーがなくても開けて、フォルダごと別の場所に移しても、そのまま Wiki として読めます。場所は `serve.pages` で変えられます。

ページの内容（ID、題名、本文の Markdown、引用）は、各ファイルの末尾にある `<script type="application/json" id="knowledge-nest-page">` に、そのまま読める JSON で入っています。Knowledge-Nest はページをここから読み、画面に見える部分はここから作ります。この JSON を書き換えると、ページが変わります。見える部分だけを書き換えた場合は、次にそのページが更新されたときに JSON の内容で作り直されます。

| ファイル | 内容 |
|---|---|
| `index.html` | 目録。すべてのページをフォルダごとに、1行の要約、出典の数、更新日とともに並べる。上の欄に語を書くと、題名と要約で絞り込める。下に、資料の追加・質問・修正・点検のコマンドを載せる |
| `log.html` | 作業の記録。終わった作業を古い順に並べ、新しい作業は末尾に足す。1件は `[2026-01-02] ingest \| スクラムガイド.md` のように、日付（UTC）、したこと（`ingest`、`query`、`lint` など）、対象で始まる |
| `フォルダ/ページ.html` | ページ。ページ ID がそのままパスになる。左上の **目録** で `index.html` に戻れる。節が3つ以上あると目次が付き、本文の引用番号を押すと下の出典に飛ぶ |

ページのファイルの中のリンクは、ファイルからの相対パスです。ほかのページへのリンクは `スプリント.html` や `../トヨタ生産方式/かんばん.html` の形になり、プロジェクト内の原本へのリンクも `../../資料/スクラム.md` の形になります。プロジェクトのフォルダごと別の場所へ移しても、リンクは切れません。プロジェクトの外にある原本は `file:` の URL のままです。

`index.html` は、取り込み、質問、指示、検査、アーカイブ、取り消しのたびに書き直されます。`log.html` には、そのたびに新しい作業が足されます。各作業の見出しは行の先頭にあるので、`grep "^<h2>\[" log.html | tail -5` で最後の5件が出ます。目録の1行の要約は、ページの最初の文です。`sources`、`entities`、`concepts` のフォルダは、「資料の要約」「人・組織・もの」「考え方・用語」の名前で並びます。古い形のページのファイルと記録は、このときに新しい形に書き直されます。これは Karpathy の LLM-Wiki の `index` と `log` にあたります。同じ名前のページがあるとき、または Knowledge-Nest が書いたものでない同名のファイルがあるときは、書きません。

## 画面から資料を追加する

1. 左上の **資料を取り込む** を開き、**URL** に Web のページの URL を書くか、**ファイル** でローカルのファイルを選び、**取り込む** を押します。選んだファイルは `raw/` に保存されます。同じ名前で中身の違うファイルがあれば、名前の後ろに中身のハッシュの先頭8文字を付けて別に保存します。プロジェクトのフォルダにあるファイルは、**プロジェクト内のファイルを指定する** にパスを書いても取り込めます。
2. 右に出る作業の欄で、取得・読み取り・執筆・引用検証の進捗を確認します。別の画面へ移動した場合は **作業の履歴** から開き直せます。
3. 完了後、変更されたページを開き、本文と出典を見比べます。出典の資料名を押すと、その原本の本文が右に出ます。

URL は http と https に対応し、HTML、PDF、Markdown、テキスト、Office 文書を取り込めます。Shift_JIS や EUC-JP のページは UTF-8 に直して保存します。取得した内容は `raw/<ホスト名>/<パス>` に原本として保存され（例：`raw/example.com/manuals/pump.html`）、ページの出典は元の URL を指します。同じ URL をもう一度取り込むと、同じ資料の新しい版になります。CLI でも `nest ingress https://example.com/page` のように URL を渡せます。

`serve` の画面を他の人にも開く場合（`serve.host` を `127.0.0.1` 以外にする場合）は、`serve.access.auth` で認証を付けてください。家や職場の LAN の中だけに開くなら、`serve.access.allowed_clients` に `192.168.11.0/24` のような範囲を書くと、範囲の外からの接続を断ります。この場合は認証なしでも起動できますが、範囲の中の端末はだれでも読み書きでき、画面からこのマシンのファイルをパスで取り込めます。設定の例は [ガイド](guide.md) の `serve` の節にあります。この PC のすべてのプロジェクトにまとめて設定するなら、`nest config set serve --host 0.0.0.0 --allowed-hosts localhost,127.0.0.1,192.168.11.16 --allowed-clients 192.168.11.0/24` のようにコマンドで書けます。画面から渡した URL は、`serve` を動かしているマシンから取得されます。

CLI の `ingress` も作業 ID を表示します。別の端末でプロジェクトを開き、`WORK_ID` を表示された ID に置き換えると進捗を確認できます。

```sh
nest progress WORK_ID --json
```

## 質問し、ページを直す

ページを探すには、目録のいちばん上の欄に語を書いて **検索** を押します。空白で区切った語のすべてを、題名か本文に含むページが出ます。AI は使いません。Wiki 全体への質問は、目録の **AI に質問する** に書いて **質問する** を押します。1つのページについて聞くときは、そのページを開き、下の **このページでできること** の **質問する** に書きます。本文を選択してから質問すると、その範囲についての質問になります。

ページを直すときは、同じ場所の **AI に指示して直す** に指示を書き、**指示を実行** を押します。本文を選択すると、対象の範囲に入ります。資料にない内容を根拠にする場合は、**資料にない内容を補足する** を開き、その内容と記録者を入力します。

CLI では以下の `PAGE_ID` を対象の ID に置き換えます。`cite` に渡す番号は、ページ内の引用番号です。

```sh
nest query "ポンプの点検はいつですか" --page PAGE_ID
nest cite PAGE_ID 1
nest instruct PAGE_ID "点検前の確認事項を箇条書きにしてください"
```

今後の作業にも使う決まりは、左の **運用の決まり** を開き、**決まりを追加する** に書いて登録します。CLI では `nest instruct --persistent` です。

## 検査して、必要な変更を取り消す

**検査** は、次のことを AI を使わずに確かめます。

| 指摘 | 内容 |
|---|---|
| `CITATION_MISSING` | 引用した箇所が原本に見つからない |
| `STALE_VERSION` | 引用した原本が新しくなっている |
| `BROKEN_LINK` | リンク先のページがない |
| `ORPHAN_PAGE` | どのページからもリンクされていない |
| `MISSING_LINK` | ほかのページの題名に触れているのに、そのページへのリンクがない |

**内容を検査** はモデルを使い、変更したページと関連ページの食い違い、資料との食い違い、重複を調べます（`CONTENT_CANDIDATE`）。全体を検査したときは、ページに出てくるのにページのない概念（`MISSING_PAGE`）と、次に調べるとよい問い、探すとよい資料も挙げます（結果の `suggestions`）。概念は、挙げられたページの本文にその語があるときだけ指摘にします。ページが変わらなければ、この提案はもう一度モデルに聞かずに前の結果を返します。CLI の検査も、作業の記録に残ります。全体の検査はホームの **点検する** から、1つのページの検査はそのページの **検査・アーカイブ** から行います。指摘に表示された引用と出典を開いて確認します。

```sh
nest lint
nest lint --content
```

変更を戻すには **作業の履歴** で対象の作業を開き、**取り消す** が表示されていれば押します。CLI では同じ作業 ID を `nest undo WORK_ID` に渡します。ページをしまうには、そのページの **検査・アーカイブ** の **アーカイブする** を押します。戻すには、左の **アーカイブ** からページを開いて **アーカイブから戻す** を押すか、`nest archive PAGE_ID --restore` を使います。
