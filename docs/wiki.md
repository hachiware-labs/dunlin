# Wiki・PARA の使い方

Wiki は資料をもとにページを書き、資料が増えるたびに書き足します。PARA は同じ操作で、Projects・Areas・Resources・Archives に沿ってノートを整理します。

## 最初のページを作る

リポジトリのルートで、ローカル Ollama を起動し、`qwen3:4b` を用意します。例では [サンプル資料](../examples/manuals/maintenance.md) を使います。

```sh
nest init wiki ./wiki-demo --purpose "設備保全の手順をまとめる" --llm-provider ollama --llm-model qwen3:4b --no-ocr
cd wiki-demo
cp ../examples/manuals/maintenance.md raw/
nest ingest raw/maintenance.md
nest serve
```

ブラウザで `http://127.0.0.1:4319` を開きます。PARA を作る場合は `init para ./para-demo` に読み替えます（PARA には `raw/` はなく、ページは `site/` に置かれます）。

`nest init wiki` が作るプロジェクトは、次の形です。

```
wiki-demo/
├─ raw/                    ← 原本。集めた資料を置く。AI は読むだけで書き換えない
├─ wiki/                   ← Wiki。AI が書くページ（HTML）
│   ├─ index.html          ← 目録
│   ├─ log.html            ← 作業の記録
│   ├─ 要約-スクラムガイド.html  ← 資料ごとの要約ページ（原本ではない）
│   ├─ スプリント.html
│   └─ …                   ← ページはフォルダに分けず平らに置く
├─ rules.md                ← 決まり。分類、ページの書き方、取り込みの手順
├─ KnowledgeNestfile.yaml  ← 使うモデルなどの設定
└─ .knowledge-nest/        ← 原本から取り出した本文と版、作業の記録（作り直せる控え）
```

`nest ingest` と `nest lint` が、取り込みと点検のコマンドです。前の名前の `nest ingress` と `nest verify` も受け付け、同じ動きをします。

## LLM-Wiki との対応

Wiki は、Andrej Karpathy の [LLM-Wiki](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f) の形に沿っています。

| LLM-Wiki | Knowledge-Nest |
|---|---|
| 原本（raw sources）。人が集め、AI は読むだけ | `raw/`。`raw/` の外から取り込んだファイル、画面から上げたファイル、URL から取った資料も、ここにコピーしてから読む |
| Wiki。AI が書いて保つページ | `wiki/` の HTML ファイル。このファイルがページそのもの |
| 決まり（schema） | `rules.md`。分類、ページの書き方、取り込みの手順 |
| 取り込み（ingest） | `nest ingest`。資料を読み、関係するページを書き直すか書き足し、足りないページを作る |
| 質問（query） | `nest query`。残したい答えは `nest save-answer` でページにする |
| 点検（lint） | `nest lint`、`nest lint --content` |
| `index`（目録） | `wiki/index.html` |
| `log`（記録） | `wiki/log.html` |

ページは Markdown で書き、末尾に、書くのに使った資料（出典）を並べます。文ごとの出典は付けません。その代わり、本文の数字・日付・「」の引用が出典の資料にそのままあるかを、プログラムが照らします（AI は使いません）。資料にないものは、取り込みの警告と `nest lint` の指摘（`UNSUPPORTED_LITERAL`）に出ます。

### 取り込みの進み方

1. 資料を `raw/` に置き、本文を取り出します。`raw/` の外のファイルは `raw/` にコピーしてから読みます。ファイルはその名前で `raw/` 直下に（`nest ingest ../manuals/pump.md` なら `raw/pump.md`）、フォルダはその名前のフォルダごと（`nest ingest ../manuals` なら `raw/manuals/…`）コピーします。コピーには元のファイルの更新日時を引き継ぎます。同じ名前で中身の違うファイルが `raw/` にあれば上書きせず、名前の後ろに中身のハッシュの先頭8文字を付けて別に置きます。同じファイルを変えてから取り込み直すと、同じ資料の新しい版になります。
2. AI に、新しい資料の名前（ファイル名か URL）と本文、決まり（`rules.md`）、いまあるページの一覧を渡します。
3. AI が、書き足すページと新しいページを Markdown で返し、それぞれに使った資料の番号を添えます。資料の番号がないページは、渡したすべての資料から書いたものとします。Wiki に足すことがなければ、ページを返しません。
4. ページを保存し、使った資料をそのページの出典に加えます。同じ資料の古い版は新しい版に置き換わります。本文の数字・日付・「」の引用で、出典の資料にないものは警告に出します。
5. どのページにも使われなかった資料は **得るものなし** として記録します（作業の結果の `no_material`、記録の「得るものなし：…」、目録と画面の `raw/` の表示）。もう一度取り込む必要はありません。

すでにあるページの扱いは、モデルによって2通りあります。`ingress` の `wiki.write` の `update` で選べます。

| `update` | 既定になるモデル | すでにあるページの扱い |
|---|---|---|
| `rewrite`（書き直す） | OpenAI、Strata | AI がまずページの一覧（ID、題名、書き出し）から、資料が関係するページを選びます。選んだページは本文を渡します。AI はそのページを新しい資料を踏まえて書き直し、食い違いがあれば両方を残して書きます。Karpathy の取り込みと同じ形で、モデルの呼び出しは2回です |
| `append`（書き足す） | Ollama | AI には本文を渡さず、返ってきた本文のうち、ページにまだない段落を末尾に足します。前の本文は消えません。小さいモデルは、ページの本文を見るとそれを写すだけで、新しい資料を書き足さないためです（`qwen3:4b` で確かめました） |

```yaml
ingress:
  modules:
    # ...
    - use: wiki.write
      with:
        model: writer
        rules: ./rules.md
        max_pages_per_job: 20
        update: rewrite
```

- 書き直しのページは、AI が返したものがそのまま新しいページになります。意図しない書き直しは `nest undo` で戻せます。
- 書き足しでは、取り込みの時点で前の記述との食い違いに気づきません。食い違いと重複は `nest lint --content` で見つけ、`nest instruct` で直します。
- 資料の新しい版を取り込むと、その資料を出典に持つページは、どちらの方法でも本文を渡して書き直させます。
- AI が本文に ` [1]` のような資料の番号を書いたときは、外して保存します。
- ページを書くときは、モデルに出力の上限を渡しません。モデルが書ける最大の長さまで書けます。待つ時間は 30 分までです。RAG の `ask` の回答には、これまでどおり上限（1024 トークン、OpenAI は 2048）を渡します。

### 決まり（`rules.md`）

`nest init wiki` は、次の内容の `rules.md` を作ります。取り込みと指示のたびに AI に渡されます。自分の分野に合わせて書き換えてください。

- 分類：ページを、何についてのページかで分ける（ページの種類では分けない）。最初は空で、取り込みで AI が付けた新しい分類が足されていく
- ページ：ID はフォルダを付けない名前にする。人・もの、考え方・用語はそれぞれのページにまとめる。その資料ならではの内容があるときだけ、要約ページ（`要約-<資料の名前>`）を作る。全体をまとめるページは作らず、全体は目録で見る
- 書き方：Markdown で書く、最初の文でそのページが何についてのものかを言う、資料にあることだけを書き、数字・日付・名前・引用は資料のとおりに書く、関係するページへリンクする、食い違いは消さずに書く
- 取り込みの手順：ものと考え方のページを書き足すか作る、必要なら要約ページを書く、Wiki に足すことのない資料ではページを書かない

### 分類

Karpathy の LLM-Wiki では、目録（index）を種類ごとに分けて並べます。Knowledge-Nest の Wiki では、この種類を「何についてのページか」という関心の分類にしています。フォルダは分けず、ページはすべて `wiki/` に平らに置きます。

- **分類の一覧**：`rules.md` の `## 分類` の下に、`- 名前` か `- 名前：説明` の形で並べます。目録と画面は、この順に並びます。
- **分類が足されるとき**：取り込みで、AI は一覧の分類からページに合うものを選びます。どれも合わないときは、いくつものページがまとまる広さの新しい分類を付け、その分類が一覧に足されます。一覧は人が自由に書き換えられます（まとめる、名前を変える、順を変える）。AI は足すだけで、分類を消したり名前を変えたりはしません。書き換えたあと、一覧から外れた分類のページは `nest lint` が `UNKNOWN_CATEGORY` として示すので、付け替えます。
- **ページの分類**：各ページのファイルの末尾の JSON の `category` にあります。取り込みでは、新しいページに AI が分類を付けます。すでにあるページの分類は、取り込みでは変えません。
- **付け替え**：`nest instruct <ページ> --category <分類>` で付け替えます。AI は使わず、`nest undo` で戻せます。ページのファイルの JSON を直接書き換えてもかまいません。
- **点検**：`nest lint` で、分類のないページ（`NO_CATEGORY`）と、一覧にない分類のページ（`UNKNOWN_CATEGORY`）を指摘します。`nest lint --content` では、AI が分類の合っていないページと、一覧のうち合っている分類を挙げます（`CATEGORY_MISMATCH`）。画面ではこの指摘に **分類を「…」にする** ボタンが出ます。

PARA は `Projects/`・`Areas/`・`Resources/`・`Archives/` の下に、取り組み・領域・話題ごとのフォルダで分けます。`init para` の `rules.md` には、人が取り組みを書く `## Projects`、領域を書く `## Areas`、AI が話題を足す `## Resources`、アーカイブした取り組みが並ぶ `## Archives`、ノートの書き方と置き場所の決め方が入ります。ノートは資料1件ごとに1つで、資料の写しはノートと同じフォルダの `資料/` に置かれます。`nest archive Projects/<取り組み>` は、そのノートと資料をフォルダごと `Archives/<取り組み>` へ移します。詳しくは [PARA 入門](start-para.md) にあります。すでにあるプロジェクトの `rules.md` は変わりません。

PARA の `nest lint` は、決まりにない取り組み（`UNKNOWN_PROJECT`）・領域（`UNKNOWN_AREA`）のノート、取り組み・領域・話題のフォルダに入っていないノート（`NO_PLACE`）、期限（`YYYY-MM-DD`）を過ぎた取り組み（`PROJECT_OVERDUE`）も指摘します。

## 画面の見かた

左の列は、どこに何があるかを示します。右の列は、開いたものと、それに対してできることを示します。

| 左の列 | 内容 |
|---|---|
| **資料を取り込む** | URL かファイルを渡して取り込む |
| **目録**、**作業の履歴**、**運用の決まり** | すべてのページの一覧、これまでの作業、AI に守らせる決まり |
| **wiki/** | AI が書くページ。`rules.md` の分類ごとに、その順に並ぶ。分類のないページは **未分類** に入る。PARA では `site/` で、フォルダのとおりに並ぶ |
| **raw/** | 集めた資料（原本）。`raw/` のフォルダとファイルのとおりに並び、URL から取った資料は `raw/` の下のホスト名のフォルダに入る。まだページに書かれていない資料には **未反映**、Wiki に足すことがなかった資料には **得るものなし**、まだ取り込んでいないファイルには **未取り込み** と出る。`raw/` の外から取り込んだ資料も `raw/` にコピーされるので、ふつうは `raw/` の中に並ぶ。この機能より前に取り込んだ資料で、`raw/` にないものは **raw/ の外** に並ぶ。`raw/` のないプロジェクトでは、見出しは **原本** で、取り込んだときのパスで並ぶ |
| **アーカイブ** | しまったページ。あるときだけ出る |

| 右の列に開くもの | 内容 | できること |
|---|---|---|
| 目録 | 目的と範囲、ページ・原本・未反映・未対応の指摘の件数、フォルダごとのすべてのページ（1行の要約付き）、最近の作業 | ページの検索、Wiki 全体への質問、未反映の原本の反映、検査 |
| ページ | 本文と、書くのに使った資料（出典）。節が3つ以上あるページには目次が付く | そのページへの質問、指示による修正、検査、アーカイブ。出典の資料名を押すと、その原本が開く |
| 原本 | 取り込んだ本文、元の URL、それを出典にしているページ | ページへの反映、URL の取り直し |
| 運用の決まり | いまの決まり | 決まりの追加 |
| 作業の履歴 | 取り込み、質問、指示、検査の記録 | 作業を開いて結果を見る、取り消す |

作業を始めると、右の列のいちばん上に、その作業の進み具合と結果が出ます。

## ページのフォルダ

ページは、1ページ1ファイルの HTML として `wiki/`（PARA は `site/`）に保存されます。このファイルがページそのもので、ほかに控えはありません。サーバーがなくても開けて、フォルダごと別の場所に移しても、そのまま Wiki として読めます。場所は `serve.pages` で変えられます。

ページの内容（ID、題名、本文の Markdown、出典の資料 `sources`、分類）は、各ファイルの末尾にある `<script type="application/json" id="knowledge-nest-page">` に、そのまま読める JSON で入っています。Knowledge-Nest はページをここから読み、画面に見える部分はここから作ります。この JSON を書き換えると、ページが変わります。見える部分だけを書き換えた場合は、次にそのページが更新されたときに JSON の内容で作り直されます。

| ファイル | 内容 |
|---|---|
| `index.html` | 目録。**wiki/** の見出しの下に、すべてのページを分類ごとに（`rules.md` の順に）、1行の要約、出典の数、更新日とともに並べる。**raw/** の見出しの下に、`raw/` のファイルをフォルダごとに並べ、それぞれ **反映済み**・**得るものなし**・**未反映**・**未取り込み** を示す。ファイル名を押すと原本が開く。上の欄に語を書くと、題名、要約、ファイル名で絞り込める。下に、資料の追加・質問・修正・点検のコマンドを載せる |
| `log.html` | 作業の記録。終わった作業を古い順に並べ、新しい作業は末尾に足す。1件は `[2026-01-02] ingest \| スクラムガイド.md` のように、日付（UTC）、したこと（`ingest`、`query`、`lint` など）、対象で始まる |
| `フォルダ/ページ.html` | ページ。ページ ID がそのままパスになる。左上の **目録** で `index.html` に戻れる。節が3つ以上あると目次が付く。末尾に、書くのに使った資料が出典として並び、資料名から原本が開く |

ページのファイルの中のリンクは、ファイルからの相対パスです。ほかのページへのリンクは `スプリント.html` や `../トヨタ生産方式/かんばん.html` の形になり、プロジェクト内の原本へのリンクも `../../資料/スクラム.md` の形になります。プロジェクトのフォルダごと別の場所へ移しても、リンクは切れません。プロジェクトの外にある原本は `file:` の URL のままです。

`index.html` は、取り込み、質問、指示、検査、アーカイブ、取り消しのたびに書き直されます。`log.html` には、そのたびに新しい作業が足されます。各作業の見出しは行の先頭にあるので、`grep "^<h2>\[" log.html | tail -5` で最後の5件が出ます。目録の1行の要約は、ページの最初の文です。古い形のページのファイルと記録は、このときに新しい形に書き直されます。

文ごとに引用を持っていた前の形のページ（本文に ` [1]` などの番号があるページ）は、番号を外した本文と、引用していた文書の一覧として読みます。ファイルは、そのページが次に更新されたときに新しい形で書き直されます。これは Karpathy の LLM-Wiki の `index` と `log` にあたります。同じ名前のページがあるとき、または Knowledge-Nest が書いたものでない同名のファイルがあるときは、書きません。

## 画面から資料を追加する

1. 左上の **資料を取り込む** を開き、**URL** に Web のページの URL を書くか、**ファイル** でローカルのファイルを選び、**取り込む** を押します。選んだファイルは `raw/` に保存されます。同じ名前で中身の違うファイルがあれば、名前の後ろに中身のハッシュの先頭8文字を付けて別に保存します。プロジェクトのフォルダにあるファイルは、**プロジェクト内のファイルを指定する** にパスを書いても取り込めます。
2. 右に出る作業の欄で、取得・読み取り・執筆・保存の進捗を確認します。別の画面へ移動した場合は **作業の履歴** から開き直せます。
3. 完了後、変更されたページを開き、本文と出典を見比べます。出典の資料名を押すと、その原本の本文が右に出ます。

URL は http と https に対応し、HTML、PDF、Markdown、テキスト、Office 文書を取り込めます。

Web のページは、このマシンの Chrome か Edge で、**nest 専用のプロファイル**を使って開きます。Wiki、PARA、`loader.auto` で URL を取り込むには、この専用プロファイルが必要です。最初に1回、次のコマンドで専用プロファイルのブラウザを開き、読ませたいサイトにログインしてからブラウザを閉じてください。

```sh
nest browser https://x.com/login
```

専用プロファイルは、ユーザー設定（`~/.knowledge-nest/config.yaml`）と同じフォルダの `browser/chrome`（Edge なら `browser/edge`）に作られます。`KNOWLEDGE_NEST_GLOBAL_CONFIG` でユーザー設定の場所を変えたときは、その隣に作られます。ふだん使うプロファイルとは別なので、ログインはここで改めて行います。ログインは取り込みのたびに引き継がれるので、定期的な取り込みも人の手なしで動きます。

| コマンド | 動き |
|---|---|
| `nest browser [<URL>]` | 専用プロファイルのブラウザを、画面ありで開く。プロファイルがなければ作る。ブラウザを閉じるとコマンドが終わる |
| `nest browser --status` | 使うブラウザ、専用プロファイルの場所、作られているか、いま開いているかを表示する |
| `nest browser --reset` | 専用プロファイルを消す。ログインの状態もすべて消える |
| `nest browser --browser edge` | Edge の専用プロファイルを開く（`--status`、`--reset` にも付けられる） |

取り込むときは、ブラウザを画面を出さずに専用プロファイルで起動し、ページを開きます。読み込みが終わって通信が 0.5 秒途切れるまで（長くても 30 秒）待ち、そのとき表示されている HTML を原本にします。スクリプトで本文を描くページも、ログインが要るページも、表示されたとおりに取り込めます。終わるとブラウザを閉じます。PDF や Markdown のようにページでないものは、ブラウザで描かずにそのままダウンロードします。どの取り方で取ったか（ブラウザとその版、または `http`）は、作業の結果の `fetched` に残ります。

次のときは、ページを読まずに止まります。ログインしていない状態で見えるページだけが取り込まれ、ほかが抜け落ちることのないよう、HTTP には切り替えません。

| エラー | 起きるとき | 直し方 |
|---|---|---|
| `BROWSER_NOT_READY` | 専用プロファイルがまだない | `nest browser` を実行し、ログインしてから閉じる |
| `BROWSER_BUSY` | 専用プロファイルが開いている（`nest browser` のウィンドウ、または別の取り込み） | ブラウザを閉じるか、別の取り込みが終わるのを待つ |
| `BROWSER_SIGNED_OUT` | ページがログインの画面へ移した（ログインの期限切れなど） | `nest browser <URL>` でログインし直す |
| `BROWSER_NOT_FOUND` | Chrome も Edge も見つからない。または `browser` に書いたブラウザがない | Chrome か Edge を入れる |

| 指定 | 動き |
|---|---|
| 既定（`loader.auto` の `fetch: browser`、`browser: auto`） | Chrome、Edge、Chromium の順に、専用プロファイルのあるものを使う |
| `browser: chrome`、`browser: edge`、実行ファイルのパス | そのブラウザだけを使う |
| `fetch: http`、または `nest ingest --fetch http <URL>` | ブラウザを使わず、HTTP で1回ダウンロードする。スクリプトは動かず、ログインの状態もない |

```yaml
ingress:
  modules:
    - use: loader.auto
      with:
        unsupported: error
        ocr: none
        fetch: browser   # browser か http
        browser: auto    # auto、chrome、edge、または実行ファイルのパス
        scroll: 0        # 下へ送って続きを読み込む回数（0〜500）。省くと 0
        follow: true     # X の投稿の言及先も読む。省くと true
```

X のブックマークのように、下へ送るほど続きが出てくるページは、`--scroll <回数>` を付けて取り込みます。

```sh
nest ingest https://x.com/i/bookmarks --scroll 100
```

ページを画面の8割ずつ下へ送り、送るたびに読み込みを待ちます（長くても2秒）。3回続けて何も増えなければ、回数の前でも止めます。このようなページは、見えなくなった投稿を画面から消していくので、送るたびに表示された投稿（`article` 要素）をその場で集め、最後に、出てきた順に1件ずつ並べた1つのページとして保存します。同じ投稿は、その投稿へのリンク（日時の付いたリンク）か本文で見分け、1度だけ入れます。投稿が2件未満のページは、最後に表示されていたとおりに保存します。回数を使い切ってもまだ続きがあったときは `FETCH_WARNING` の警告を出します。何回送り、投稿をいくつ集めたかは、作業の結果の `fetched` の `scrolled`（`steps`、`items`）に残ります。いつも送るなら、`loader.auto` の `scroll` に回数（0〜500）を書けます。`--scroll` はそれより優先です。

### X の投稿と、その言及先

X のページ（ブックマーク、タイムライン、1件の投稿）は、ページの見た目ではなく、X がページを描くために読み込む投稿のデータから取り込みます。データには、投稿の全文、短縮リンク（`t.co`）の元の URL、引用された投稿が入っているためです。

- **投稿1件が1つの資料**: 投稿ごとに `raw/x.com/<ユーザー>/status/<ID>.html` を作り、出典は `https://x.com/<ユーザー>/status/<ID>` を指します。ページには、投稿者、日時、本文（リンクは元の URL）、画像や動画の場所、引用された投稿が入ります。いいねの数のように、読むたびに変わるものは入れません。
- **言及先も読む（標準）**: 投稿の本文のリンク先と、引用された投稿も、それぞれ1つの資料として取り込みます。たどるのは1段だけで、言及先のページの中のリンク、プロフィール、ハッシュタグ、画像、返信はたどりません。X の長文の記事（`x.com/i/article/...`）は、記事のページを表示されたとおりに取り込みます。どの投稿から読んだかは、作業の結果の `followed`（`url`、`from`、`with`）に残ります。
- **すでにある資料は読み直さない**: すでに資料になっている投稿と言及先は、もう一度は読みません。同じブックマークを定期的に取り込むと、新しい投稿と、まだ読んでいない言及先だけが増えます。
- **読めなかった言及先**: ログインの画面へ移されたページや、開けなかったページは、`FETCH_WARNING` の警告にして飛ばします。投稿は取り込まれます。1回の取り込みでブラウザで開く言及先は 30 件までで、残りは次に取り込むときに読みます（引用された投稿は、引用した投稿のデータに入っているので、この数に入りません）。
- **言及先を読まない**: `nest ingest <URL> --no-follow`、または `loader.auto` の `follow: false` で、投稿だけを取り込みます。

```sh
nest ingest https://x.com/i/bookmarks --scroll 100
nest ingest https://x.com/i/bookmarks --scroll 100 --no-follow
```

作業の結果の `fetched` には、X のページから読んだ投稿の数が `posts` に出ます。

Shift_JIS や EUC-JP のページは UTF-8 に直して保存します。取得した内容は `raw/<ホスト名>/<パス>` に原本として保存され（例：`raw/example.com/manuals/pump.html`）、ページの出典は元の URL を指します。同じ URL をもう一度取り込むと、同じ資料の新しい版になります。CLI でも `nest ingest https://example.com/page` のように URL を渡せます。

`serve` の画面を他の人にも開く場合（`serve.host` を `127.0.0.1` 以外にする場合）は、`serve.access.auth` で認証を付けてください。家や職場の LAN の中だけに開くなら、`serve.access.allowed_clients` に `192.168.11.0/24` のような範囲を書くと、範囲の外からの接続を断ります。この場合は認証なしでも起動できますが、範囲の中の端末はだれでも読み書きでき、画面からこのマシンのファイルをパスで取り込めます。設定の例は [提供する入口と、接続を許す相手を決める](serve.md) にあります。この PC のすべてのプロジェクトにまとめて設定するなら、`nest config set serve --host 0.0.0.0 --allowed-hosts localhost,127.0.0.1,192.168.11.16 --allowed-clients 192.168.11.0/24` のようにコマンドで書けます。画面から渡した URL は、`serve` を動かしているマシンから取得されます。

CLI の `ingest` も作業 ID を表示します。別の端末でプロジェクトを開き、`WORK_ID` を表示された ID に置き換えると進捗を確認できます。

```sh
nest progress WORK_ID --json
```

## 質問し、ページを直す

ページを探すには、目録のいちばん上の欄に語を書いて **検索** を押します。空白で区切った語のすべてを、題名か本文に含むページが出ます。AI は使いません。Wiki 全体への質問は、目録の **AI に質問する** に書いて **質問する** を押します。1つのページについて聞くときは、そのページを開き、下の **このページでできること** の **質問する** に書きます。本文を選択してから質問すると、その範囲についての質問になります。

ページを直すときは、同じ場所の **AI に指示して直す** に指示を書き、**指示を実行** を押します。本文を選択すると、対象の範囲に入ります。資料にない内容を根拠にする場合は、**資料にない内容を補足する** を開き、その内容と記録者を入力します。

CLI では以下の `PAGE_ID` を対象の ID に置き換えます。`cite` に渡す番号は、ページの出典の番号（1から）です。その資料と、いまの本文を返します。

```sh
nest query "ポンプの点検はいつですか" --page PAGE_ID
nest cite PAGE_ID 1
nest instruct PAGE_ID "点検前の確認事項を箇条書きにしてください"
```

今後の作業にも使う決まりは、左の **運用の決まり** を開き、**決まりを追加する** に書いて登録します。CLI では `nest instruct --persistent` です。

## 検査して、必要な変更を取り消す

**検査** は、次のことを AI を使わずに確かめます。

| 指摘 | 内容 |
|---|---|
| `SOURCE_MISSING` | 出典の資料がプロジェクトにない |
| `STALE_VERSION` | 出典の資料が新しくなっている（新しい版をまだページに反映していない） |
| `UNSUPPORTED_LITERAL` | 本文の数字（2桁以上）・日付・「」『』“” の引用が、出典の資料のどれにもない。資料の名前と `rules.md`（取り組みの期限など）にあるものは指摘しない。空白と数字の桁区切りの `,` は区別しない |
| `BROKEN_LINK` | リンク先のページがない |
| `ORPHAN_PAGE` | どのページからもリンクされていない |
| `MISSING_LINK` | ほかのページの題名に触れているのに、そのページへのリンクがない |
| `NO_CATEGORY` | ページに分類がない（Wiki のみ） |
| `UNKNOWN_CATEGORY` | ページの分類が `rules.md` の分類の一覧にない（Wiki のみ） |

**内容を検査** はモデルを使い、変更したページと関連ページの食い違い、資料との食い違い、重複を調べます（`CONTENT_CANDIDATE`）。全体を検査したときは、ページに出てくるのにページのない概念（`MISSING_PAGE`）、分類の合っていないページ（`CATEGORY_MISMATCH`。一覧にある、合っている分類を添える）、次に調べるとよい問い、探すとよい資料も挙げます（結果の `suggestions`）。概念は、挙げられたページの本文にその語があるときだけ指摘にします。ページが変わらなければ、この提案はもう一度モデルに聞かずに前の結果を返します。CLI の検査も、作業の記録に残ります。全体の検査はホームの **点検する** から、1つのページの検査はそのページの **検査・アーカイブ** から行います。指摘に表示された引用と出典を開いて確認します。

```sh
nest lint
nest lint --content
```

変更を戻すには **作業の履歴** で対象の作業を開き、**取り消す** が表示されていれば押します。CLI では同じ作業 ID を `nest undo WORK_ID` に渡します。ページをしまうには、そのページの **検査・アーカイブ** の **アーカイブする** を押します。戻すには、左の **アーカイブ** からページを開いて **アーカイブから戻す** を押すか、`nest archive PAGE_ID --restore` を使います。
